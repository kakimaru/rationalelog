# ペルソナ
- 事業会社で働く UI/UX デザイナー。実務 3〜5 年目
- 副業（業務委託・スポット案件）を始めたいと考えている
- 副業の応募にはポートフォリオが必要だとわかっている。ただ期限がないので後回しにしてしまう
- 業務中は記録する余裕がない。余裕がある日（週に 1〜3 回）に思い出して書く程度
- 守秘義務のある案件が多く、成果物の画像は出せない。そのため、プロセスを言葉で語れることが必要になる

## as-is / to-be

| 場面 | as-is | to-be |
|---|---|---|
| 記録 | 何を書けばいいかわからず、手が止まる | ざっくり一言書けば、AIが問いかけて判断理由を引き出してくれる |
| 整理 | プロジェクトごとに分けるのが面倒 | AIがプロジェクト候補を出すので、確定するだけで済む |
| 活用 | 応募するときには記憶が薄れていて、まとめるのに時間がかかる | 溜まったログから、ケーススタディの下書きがすぐ出る |
| 副次効果 | — | 問いに答えることが、デザインを言語化する練習になる |

## 設計上の前提（ペルソナから導いたもの）
- 毎日書くことを前提にしない。連続記録（streak）やノルマは作らず、間が空いても罪悪感を与えない
- 入力は 1 行でよい。種別やプロジェクトを選ばないと書けない、という作りにしない
- 深掘りは任意にして、スキップできるようにする

# ユーザーフロー
1. **記録**：ホームの入力欄に、今日やったことを自由に書く。種別（判断 / FB / 成果 / 学び）は任意で選ぶ
2. **振り分け**：保存する前に、AI（モック）がプロジェクトの候補を出す。ユーザーはそのまま確定するか、変更するか、新しく作る
3. **深掘り（任意）**：保存したあと、種別に応じた質問を 1〜2 個表示する。答えるとログに追記される。スキップもできる
4. **蓄積の確認**：プロジェクトごとにログを一覧する。件数や、深掘り済みのログの数が見える
5. **活用**：副業に応募するときに、プロジェクトを選ぶ → ログを選ぶ → ケーススタディの下書きを生成する → 編集して保存する

# 必要な機能

| 優先度 | 機能 | 対応するフロー | 備考 |
|---|---|---|---|
| Must | ログの CRUD（本文・種別・プロジェクト・日付） | 1, 4 | 種別は任意。選ばなかった場合は「未分類」 |
| Must | プロジェクトの CRUD | 2, 4 | 振り分けの画面からも新規作成できる |
| Must | AIによるプロジェクト候補の提案（モック） | 2 | `mockAi.ts` の `suggestProject(log, projects)`。プロジェクト名やキーワードと一致するものを返す。一致しなければ直近に使ったプロジェクトを返す |
| Must | AIの深掘り質問（モック） | 3 | `mockAi.ts` の `getDeepDiveQuestions(log)`。種別ごとに固定の質問を返す。回答はログに保存する |
| Must | ケーススタディの生成と CRUD（モック） | 5 | `mockAi.ts` の `generateCaseStudy(project, logs)`。背景 / 課題 / プロセス / 判断理由 / 成果 / 学び のテンプレートにログを差し込む |
| Must | 「デモ版のため固定の応答です」の表示 | 2, 3, 5 | AIの応答を出す画面すべてに表示する |
| Should | プロジェクトごとの蓄積の表示（件数・深掘り済みの数） | 4 | ケーススタディにできるかどうかの目安を示す |
| Should | 初回利用時のサンプルデータと、空の状態のガイド | 1 | 面接でデモを見せやすくする |
| Won't（MVP外） | リマインド通知 / 守秘版の生成 / PDF書き出し / 職務経歴書の出力 / 認証 / 課金 | — | バックエンドが必要、または MVP の範囲外。Pro プランの機能として concept に残す |

## データ項目
型の詳細は各機能の仕様を参照する。
- **Project**：`features/project/requirements.md`
- **Log**：`features/log/requirements.md`
- **CaseStudy**：`features/case-study/requirements.md`

# 決めたこと
- **画面は 3 つ**（ホーム / プロジェクト詳細 / ケーススタディ編集）。記録・振り分け・深掘りはホームの中でモーダルとして完結させる → `features/screens/requirements.md`
- **画面の切り替えは URL のハッシュ**（`#/projects/:id` など）を自前で読む。パッケージは追加しない
- **1 件のログは 1 つのプロジェクトに紐づける**。複数にまたがる場合は、ログを分けて書いてもらう
- **深掘りの回答は、ログ本文とは別の欄で持つ**。本人が書いた一次情報と、問いに答えて出てきた情報を区別するため
