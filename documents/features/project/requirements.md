# プロジェクト

対応するフロー：`userflow.md` の 2（振り分け）・4（蓄積の確認）

## データ

```ts
type Project = {
  id: string;
  name: string;        // 必須。1〜50 文字
  description: string; // 任意。ケーススタディの「背景」の元になる
  keywords: string[];  // 任意。振り分けの推定に使う（例：['オンボーディング', 'LP']）
  createdAt: string;
  updatedAt: string;
};
```

- 保存キー：`rationale-log:projects`
- `updatedAt` は、プロジェクトを編集したときと、そのプロジェクトにログを追加したときに更新する（振り分けで同点のときの判定に使う）

## 操作
| 操作 | 場所 | 内容 |
|---|---|---|
| 作成 | ホームの「プロジェクトを追加」、振り分けモーダルの「新しいプロジェクトを作る」 | 振り分けモーダルでは名前だけ入力する。説明・キーワードはあとで追加できる |
| 一覧 | ホーム | カードで表示。並び順は `updatedAt` の新しい順 |
| 編集 | プロジェクト詳細 | 名前・説明・キーワード（カンマ区切りで入力する） |
| 削除 | プロジェクト詳細 | 確認モーダル（「ログ ◯件とケーススタディ ◯件も一緒に削除されます」）。紐づくログとケーススタディも削除する |

## 守秘への配慮（MVP の範囲）
- プロジェクト名は、社名や案件名をそのまま書かなくてもよいことを、入力欄の補足に書く（例：「社名を伏せた呼び名でも大丈夫です」）
- 固有名詞を伏せた版を生成する機能は Pro 機能として扱い、MVP では作らない
