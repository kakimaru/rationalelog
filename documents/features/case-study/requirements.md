# ケーススタディ

対応するフロー：`userflow.md` の 5（活用）

## データ

```ts
type CaseStudySections = {
  background: string; // 背景
  problem: string;    // 課題
  process: string;    // プロセス
  rationale: string;  // 判断理由
  outcome: string;    // 成果
  learning: string;   // 学び
};

type CaseStudy = {
  id: string;
  projectId: string;
  title: string;      // 初期値は「<プロジェクト名> のケーススタディ」
  logIds: string[];   // 生成に使ったログ（参照用）
  sections: CaseStudySections;
  createdAt: string;
  updatedAt: string;
};
```

- 保存キー：`rationale-log:case-studies`
- セクションはログの文章をコピーして持つ。元のログを編集・削除しても、ケーススタディは変わらない（下書きとして手で直していくものなので）

## 生成のフロー（プロジェクト詳細 → ケーススタディ編集）
1. プロジェクト詳細で「ケーススタディを作る」を押す
2. ログ選択のモーダル：そのプロジェクトのログを、すべて選んだ状態で表示する。チェックを外して除外できる
   - 選んだログが 0 件のときは「生成する」を押せない
   - ログが 3 件未満のときは「ログが少ないと下書きが薄くなります」と補足を出す（生成はできる）
3. 「生成する」を押すと `generateCaseStudy(project, logs)` を呼ぶ（待ち時間 1 秒程度、「下書きを作っています…」と表示する）
4. 生成した内容をそのまま保存して、ケーススタディ編集（`#/case-studies/:id`）へ移動する

## 編集画面
- タイトルと 6 つのセクションをテキストエリアで編集し、「保存」で更新する
- 保存していない変更があるときに戻ろうとしたら、確認を出す
- 生成した下書きであることを示すため、画面の上部に「AIが作った下書きです。デモ版のため固定の応答です」と表示する
- 削除：確認モーダルを出してから削除し、プロジェクト詳細へ戻る

## モック AI の仕様（`src/lib/mockAi.ts`）

### `generateCaseStudy(project: Project, logs: Log[]): Promise<{ title: string; sections: CaseStudySections }>`

ログを日付の古い順に並べ、次のルールでセクションに差し込む。該当するログがないセクションは「（まだ記録がありません。ここに追記しましょう）」とする。

| セクション | 元になる情報 |
|---|---|
| 背景 | プロジェクトの説明（空なら上記の文言） |
| 課題 | FB のログの本文 |
| プロセス | すべてのログを「日付：本文」の形で時系列に並べたもの |
| 判断理由 | 判断のログの本文と、その深掘りの回答 |
| 成果 | 成果のログの本文 |
| 学び | 学びのログの本文 |

- 本文は箇条書き（`- `）でつなぐ
- 深掘りの回答は、元のログの下に「  - Q. 質問 / A. 回答」の形で入れる
