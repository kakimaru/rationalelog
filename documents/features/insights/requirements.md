# 自己分析・プロジェクトのアピールポイント

## 目的
面接課題の FB（「使い始めるきっかけがない」「記録への強い意志が前提になっている」）に応えるため、記録した結果として **自己理解** が返ってくるようにする。
「先月の自分と比べてどう変わったか」「自分の思考の癖は何か」が見えることを、記録を続けるきっかけにする。

## 方針
- 分析はすべて `src/lib/mockAi.ts` の `analyzeSelf` / `analyzeProject` で行い、`Promise` で返す（待ち時間 1 秒）。本番では AI がログを読んで分析する形に差し替える
- 分析結果は **保存しない**。画面を開くたびにログから計算する（storage に変更なし）
- 分析を表示する画面には `DemoNotice` を出す
- ログが `ANALYSIS_MIN_LOGS`（3 件）未満のときは `enough: false` を返し、画面に「あと n 件記録すると分析できます」と出す
- 削除済みのプロジェクトに残ったログは数えない
- 読み込み中は「ログを読み解いています…」（`role="status"`）。ログを変えて取り直す間は、前の結果を出したままにする

## 期間
- 「この1か月」：直近 30 日（今日から 29 日前まで）
- 「先月」：その前の 30 日（30〜59 日前）。暦の月にしないのは、月初に件数が少なく比較にならないため
- スキルの「1か月前」：30 日以上前のログ **すべて** から計算した値（その時点の自分）。該当するログがなければ `null`

## 先月の自分との比較（`MonthlyComparison`）
- 件数・深掘りに答えた割合（%）・種別ごとの件数を、今月と先月で並べる。先月のログが 0 件なら `lastMonth: null`
- `headline`（1 文）：
  1. 先月のログがない → 「この1か月で n 件の記録がたまりました。来月は今月の自分と比べられます」（今月も 0 件なら記録をすすめる文）
  2. いちばん増えた種別があれば → 「先月より◯◯の記録が n 件増えました」
  3. 全体が増えた → 「先月より記録が n 件増えました」／同じ → 「先月と同じペースで記録が続いています」／減った → 「先月より記録が n 件少なめです。余裕のある日に一言だけでも大丈夫です」（責めない）
- `notes`（最大 3 つ）：深掘りの割合の上下、いちばん伸びたスキル（+5 以上）、今月の成果の記録がないこと

## 思考の癖（`TraitAxis`、4 軸）
値は -100（左寄り）〜 100（右寄り）。`(右 - 左) / (右 + 左) × 100`。±30 を超えたら寄っている側の、そうでなければ中間のコメントを出す。
キーワードを含まないログは反対側の弱い根拠として重み 0.4 で数える。

| 軸 | 左 | 右 | 数え方 |
|---|---|---|---|
| evidence | 直感で動く | 根拠を集める | 「データ・検証・テスト・数字・%・インタビュー・調査」などを含むログ |
| collaboration | ひとりで深める | 周りを巻き込む | FB のログ、「相談・PM・エンジニア・レビュー・合意」などを含むログ |
| perspective | ユーザー視点 | ビジネス視点 | 「ユーザー・体験・離脱・面倒」など ⇔ 「売上・KPI・コスト・継続率・指標」など |
| convergence | 広げる | 決めきる | 学び・未分類の件数 ⇔ 判断・成果の件数 |

キーワードは本文と深掘りの回答の両方から探す。

## スキル（`SkillScore`、6 項目）
リサーチ／情報設計／ビジュアル／合意形成／検証・改善／言語化。
- 各スキルの根拠になるログ（キーワードを含む、または特定の種別。合意形成は FB、検証・改善は成果、言語化は深掘りに答えたログと学び）を数える
- スコア = `根拠のログの割合 × 120 + min(件数, 4) × 5` を 0〜100 に丸める（一貫性と経験の量の両方を見る）

## 画面

### 自己分析（`#/insights`）
- 上から：先月の自分と比べて（headline・件数・深掘りの割合・種別の内訳・notes）→ 思考の癖（4 本のゲージとコメント）→ スキル（レーダーチャート）→ `DemoNotice`
- ゲージ（`TraitGauge`）：左右のラベル、中央 0 の横バー、現在地のマーカー。`role="meter"` と `aria-valuenow` / `aria-valuetext` を付ける。寄っている側のラベルを強調する
- レーダー（`SkillRadarChart`）：今を塗り、1か月前を破線で重ねる。色だけに頼らないよう、凡例と数値の表を下に置く

### プロジェクト詳細の右カラム（`analyzeProject`）
- **このプロジェクトでアピールできること**：スコア 50 以上のスキルを高い順に最大 3 つ。見出し（例：「数字で検証し、改善につなげられる」）と、根拠になったログの本文を最大 2 件（2 行まで）
- このプロジェクトでの思考の癖：偏りの大きい 2 軸のゲージ（コメントなし）
- スキル：小さなレーダーと数値の表
- **この経験を作れると強い**（最大 3 つ）：
  1. ログがない種別（成果 → 判断 → FB → 学びの順。ケーススタディの章が埋まらないため）
  2. スコアが 50 未満のスキル（低い順）
  3. どれもなければ「材料はそろっています。ケーススタディにまとめてみましょう」
- ログを追加・編集・削除したら取り直す
