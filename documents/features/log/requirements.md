# ログ（記録・振り分け・深掘り）

対応するフロー：`userflow.md` の 1（記録）・2（振り分け）・3（深掘り）・4（蓄積の確認）

## データ

```ts
type LogType = 'decision' | 'feedback' | 'outcome' | 'learning';

type DeepDiveAnswer = {
  question: string;
  answer: string;
};

type Log = {
  id: string;
  projectId: string;        // 必須。振り分けで必ず決まる
  body: string;             // 本文（1 文字以上 1000 文字以内）
  type: LogType | null;     // 任意。null は「未分類」
  deepDive: DeepDiveAnswer[]; // 深掘りの回答。本文とは別に持つ
  date: string;             // 'YYYY-MM-DD'。初期値は今日。過去の日付にも変えられる
  createdAt: string;        // ISO 8601
  updatedAt: string;
};
```

- 保存キー：`rationale-log:logs`
- 種別の表示名：decision = 判断 / feedback = FB / outcome = 成果 / learning = 学び / null = 未分類

### 決めたこと
- **深掘りの回答は本文と別に持つ**：本人が書いた一次情報（本文）と、問いに答えて出てきた情報を区別できるようにするため。ケーススタディ生成のときに、回答は主に「判断理由」に使う
- **1 件のログは 1 つのプロジェクトに紐づける**：複数にまたがる場合は、ログを分けて書いてもらう。紐づけを複数にすると、振り分けの UI もケーススタディの集計も複雑になるため

## 記録のフロー（ホーム）

1. **入力（一体型のコンポーザー）**
   - ChatGPT / Claude の入力欄のように、本文・種別・日付・送信ボタンを 1 つの角丸の枠（`rounded-composer`）にまとめる。textarea は枠線なし・背景透明で、入力に合わせて高さが伸びる（`field-sizing: content`。未対応のブラウザでは 3 行で固定しスクロールする）
   - 本文の意味はスクリーンリーダー向けのラベル（「本文（今日やったこと、決めたこと、言われたことを一言で）」）で伝える。`placeholder` は使わない（下のタイプ演出と重なるため）
   - 枠の下側のツールバー：左に種別のチップ（判断 / FB / 成果 / 学び。任意で、もう一度押すと解除される）と日付（初期値は今日）、右に丸い送信ボタン（↑ アイコン、`aria-label="記録する"`）。本文が空のときは押せない
   - ⌘ / Ctrl + Enter でも送信できる（日本語の変換中の Enter は除く）
   - **タイプ演出**（書き始めのハードルを下げるための情緒的な仕掛け）
     - 本文が空のとき、書き方の例（`src/lib/composerSamples.ts`）を placeholder と同じ色で 1 文字ずつ（約 60ms ごと）打つ。点滅するキャレットを付ける。`aria-hidden`
     - 打ち終わったら 5 秒止める。その間、打ち終わりから 0.8 / 2.2 / 3.6 秒後に、その例の種別の深掘り質問を 1 つずつ（最大 3 つ）「記録すると、AIがこんなふうに問いかけます」としてチップで出す（`animate-fade-in-up`）。5 秒たったら次の例へ進む
     - 質問の例は `mockAi.ts` の `getDeepDiveQuestionsFor(type)` から取る（AI の応答にあたる文言のため）
     - 1 文字でも入力したら、演出と質問を消す。本文を空に戻すと、今の例の頭から打ち直す。モーダルを開いている間は止める
     - `prefers-reduced-motion: reduce` のときは動かさず、例の全文と質問 3 つを最初から表示する
2. **振り分け（モーダル）**
   - 「記録する」を押すと、`suggestProject(draft, projects)` を呼ぶ（待ち時間 1 秒程度、待っている間は「プロジェクトを推定しています…」と表示する）
   - 候補のプロジェクトを選んだ状態でラジオボタンの一覧を表示する。候補には「AIの提案」バッジを付け、理由（例：「『オンボーディング』が含まれています」）を添える
   - ユーザーはそのまま「このプロジェクトに保存」を押すか、別のプロジェクトを選ぶか、「新しいプロジェクトを作る」（名前を入力）を選ぶ
   - プロジェクトが 1 件もない場合は、新規作成の入力欄だけを表示する
   - 「デモ版のため固定の応答です」と表示する
   - ここで初めてログを保存する（キャンセルした場合は、入力内容を入力欄に残したまま閉じる）
3. **深掘り（モーダル、任意）**
   - 保存した直後に、`getDeepDiveQuestions(log)` の質問を 3 個表示する
   - 質問ごとに回答欄を出す。空欄の質問は保存しない
   - 「回答を保存」「あとで」の 2 つのボタン。「あとで」を押しても、ログは保存済みのまま
   - 「デモ版のため固定の応答です」と表示する
4. 完了後は入力欄を空にし、最近のログの先頭に追加する

## ログの一覧・編集・削除
- 一覧の各ログに表示する内容：日付・種別バッジ・本文・プロジェクト名（ホームのみ）・深掘り済みのマーク
- 編集（モーダル）：本文・種別・日付・プロジェクトを変えられる。深掘りの回答も編集・削除できる
- 深掘り：深掘りしていないログには「深掘りする」ボタンを出し、記録時と同じモーダルを開く
- 削除：確認モーダル（「このログを削除しますか？ケーススタディに反映済みの文章は残ります」）

## モック AI の仕様（`src/lib/mockAi.ts`）

### `suggestProject(draft: { body: string; type: LogType | null }, projects: Project[], logs: Log[]): Promise<ProjectSuggestion>`

```ts
type ProjectSuggestion = {
  projectId: string | null; // null は「候補なし（新規作成をすすめる）」
  reason: string;
};
```

判定の順番：
1. 本文に、プロジェクト名またはキーワードが含まれているプロジェクトを探す（大文字・小文字は区別しない）。一致した語の数がいちばん多いものを返す。同点の場合は、最近更新されたものを返す
   - reason：「『◯◯』が含まれています」
2. 一致がなければ、直近のログのプロジェクトを返す
   - reason：「前回記録したプロジェクトです」
3. プロジェクトもログもなければ `projectId: null`
   - reason：「最初のプロジェクトを作りましょう」

### `getDeepDiveQuestions(log: Log): Promise<string[]>`

種別ごとの固定の質問：

| 種別 | 質問 |
|---|---|
| 判断 | 「他にどんな案がありましたか？」「その案を選んだ決め手は何ですか？」「何を優先して、何をあきらめましたか？」 |
| FB | 「誰から、どんな観点のフィードバックでしたか？」「それを受けて何を変えましたか？」「納得できなかった点はありますか？」 |
| 成果 | 「どんな変化がありましたか？（数字があれば）」「その成果に効いた判断は何でしたか？」「もう一度やるなら、どこを伸ばしたいですか？」 |
| 学び | 「次に同じ場面が来たら、何を変えますか？」「その学びに気づいたきっかけは何ですか？」「他のプロジェクトでも使えそうですか？」 |
| 未分類 | 「このとき、何をなぜ決めましたか？」「誰かからの反応はありましたか？」「うまくいった点、引っかかった点はどこですか？」 |

### `getDeepDiveQuestionsFor(type: LogType | null): string[]`
- 入力欄のタイプ演出で「AIはこんなふうに問いかけます」と見せる例。上の表と同じ質問を、待ち時間なしで同期的に返す
- 演出用のため、本番でも固定の例のままでよい（AI API に差し替えない）
