# 目的とゴール
転職面接にて課題「AIプロダクト開発課題」が出た。最終的にWebデプロイを行い、最低限のCRUDを行える状態にしたい。
フロントはNext.jsかVite、バックエンドはNode.jsかTypeScript、データベースはfirebaseかCloudflareを考えているが、最適なものを選んで欲しい。
市場規模やマネタイズも考えたい。


# 課題の内容
## 概要
完成点や技術点を評価するプロセスではなく、皆さんが**どんな課題に着目し、どのようなアイデアに落とし込んだ**のか、**AIをどのように使って**アプリ・サービスとして形にしたのかをレビューさせていただきます。

動くものを開発した事実そのものではなく、**アプリ・サービス設計にどのような意図が込められているのか**を重視して、二次面接の場でお話を伺いし、面接担当よりフィードバックをお伝えさせて頂きたいと考えております。

## テーマ
**「日々の何かを記録する（ログ）アプリ」** の作成をお願いします。

個人用でも、業務用でも構いません。**誰のどんな課題を解決するのか、どんな価値提供をするのか、どんなビジネスモデルを想定しているのか**を意識しながら、あなた自身で設定してください。

- 暮らし・趣味系：日記、読書記録、気分ログ、推し活、ごはん記録 …
- 仕事・業務系：議事録ログ、案件トラッカー、ふりかえりログ、ナレッジストック …

※得意な領域で選んでいただいて構いません

※ ClaudeなどのAIで、Webアプリとして成立する範囲を想定しています（重いバックエンド開発が不要なもの）。数日あれば十分に作り切れる規模を想定しています。


# アプリアイデア

## プロダクト名（仮）
**Rationale Log（ラショナル・ログ）**
デザイナーの「なぜそうしたか（Design Rationale）」を毎日30秒で記録し、AIがポートフォリオ用のケーススタディに育てるログアプリ。

## 1. 誰のどんな課題を解決するのか
**誰の：** 事業会社で働き、副業（業務委託・スポット案件）を検討しているUI/UXデザイナー（実務3〜5年目の中堅層が中心）。詳細は `userflow.md` を参照

**どんな課題：**
- ポートフォリオや評価面談で問われるのは成果物の見た目よりも「課題をどう捉え、なぜその判断をしたか」というプロセス。しかし、いざ書く段階ではその判断理由が思い出せない
- 判断の経緯はFigmaのコメント、Slack、口頭FBに散らばって消えていく。プロジェクト終了から数ヶ月経つと再現できない
- 日報や日記のような「書くための記録」は続かない。書いても後から使える形になっていない
- 守秘義務のため、成果物をそのまま見せられない案件も多い。プロセスを言語化して語れないと、実績がないのと同じ扱いになる

**原体験：** （※ここに自分の体験を1〜2文で追記：例「転職活動でポートフォリオを作ったとき、半年前の案件の判断理由を思い出せず、成果物の画像しか並べられなかった」）

## 2. どんな価値提供をするのか
**提供価値：「書き溜めた断片が、そのまま語れる実績になる」**

| フェーズ | ユーザーの行動 | AIの役割 |
|---|---|---|
| 記録（余裕のある日） | 判断・受けたFB・成果・学びを一言で書く（30秒） | プロジェクトの候補を提案する（本人が確定） |
| 深掘り（週1程度） | AIの問いかけに答える | 「他にどんな案があった？」「何を根拠に選んだ？」などを質問し、判断理由を引き出して構造化する |
| 活用（必要な時） | プロジェクト単位でログを選ぶ | ケーススタディ（背景/課題/プロセス/判断理由/成果/学び）の下書きを生成する。守秘案件向けに固有名詞を伏せた版も作れる |

**AI活用の設計意図：**
- AIに記録を代筆させるのではなく、問いかけで本人の言語化を引き出す役割にする。書く負担は減らしつつ、思考の主体は本人に残す
- 入力は短い断片で済ませ、構造化はAIが担う。これで続けやすさと後での使いやすさを両立させる

**既存手段との違い：**
- Notion・日記アプリ：記録はできるが、ポートフォリオ化は手作業
- ポートフォリオサービス（Foriio等）：完成品を置く場所であり、プロセスを溜める場所ではない
- 本アプリ：日々の記録からケーススタディ化までを一気通貫でつなぐ

## 3. どんなビジネスモデルを想定しているのか
**B2Cのフリーミアムで個人に広め、デザイン組織向けのB2Bへ展開する**

| プラン | 価格（仮） | 内容 |
|---|---|---|
| Free | 0円 | ログ記録は無制限。AI深掘りは月10回まで。ケーススタディ生成は月1件まで |
| Pro | 月980円 | AI深掘り無制限、ケーススタディ生成無制限、守秘版生成、Markdown/PDF出力 |
| Team（B2B） | 1人あたり月1,500円 | デザイン組織向け。メンバーの判断ログを（本人が公開設定した範囲で）共有でき、評価面談・1on1用のサマリー生成、チームのナレッジ化に使える |

**展開シナリオ：**
1. 転職や評価面談の前に使いたくなるタイミングでPro課金を狙う。デザイナーコミュニティやSNSで生成したケーススタディが共有されることを流入経路にする
2. 個人利用者が社内に持ち込む形でTeamプランを導入してもらう。デザインマネージャーの評価・育成の負担を下げる価値で法人課金につなげる
3. 将来の選択肢：本人の同意を前提に、デザイナー採用支援（エージェントや採用企業）との連携

**市場規模（フェルミ推定・要検証）：**
- TAM：国内のデザイン職 約20万人 × 年1.2万円 ≒ 約24億円
- SAM：うちUI/UXデザイナー 約5万人 × 年1.2万円 ≒ 約6億円
- SOM（3年目の目標）：Pro 3,000人（約3,500万円/年）＋ Team 30社 × 10人（約540万円/年）

## MVPの範囲（課題提出版）
- **認証：** デモ版では省略。データはブラウザのlocalStorageに保存する（本番想定はFirebase Authentication + Firestore）
- **CRUD：**
  - プロジェクト（作成/一覧/編集/削除）
  - ログ（作成/一覧/編集/削除。種別：判断・FB・成果・学び）
  - ケーススタディ（生成/保存/編集/削除）
- **AI機能（デモ版はモック）：** 外部のAI APIは呼ばず、決まった文言を返して体験だけを再現する
  - ①ログへの深掘り質問：ログの種別（判断・FB・成果・学び）ごとに用意した固定の質問を返す
  - ②ケーススタディ生成：選んだログの本文をテンプレート（背景/課題/プロセス/判断理由/成果/学び）に差し込んで下書きを作る
  - ③プロジェクト候補の提案：ログ本文とプロジェクト名・キーワードの一致から候補を出し、本人が確定する。一致しなければ直近に使ったプロジェクトを提案する
  - 画面上に「デモ版のため固定の応答です」と表示する
  - AI処理は1つのモジュールにまとめ、本番ではClaude API呼び出しに差し替えるだけで済む構造にしておく

## 技術構成（推奨）
- フロント：**React + Vite + TypeScript + Tailwind CSS**
  - 理由：AI APIもログインもないデモ版はクライアントだけで完結するため、サーバー機能を持たない最小構成にする。将来AI APIを組み込むときは、Vercel Functionsなどの薄いAPIを追加する
- 認証・DB：**デモ版はログインなし + localStorage**
  - 理由：外部サービスの設定なしで公開でき、CRUDの体験を最短で見せられる。データ操作は1つのモジュールにまとめ、本番ではFirebase Authentication + Firestoreに差し替える
- AI：**デモ版はモック（固定の文言）**。本番想定はClaude API
- デプロイ：**Vercel**（静的サイトとして、GitHub連携ですぐ公開できる）
